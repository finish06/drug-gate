## Already in place (from prior CI work)

- `.github/workflows/ci.yml` `publish` job: builds/pushes `:beta` on main, `:vX.Y.Z` + `:latest` on tags
- Staging deploy via signed webhook (`STAGING_WEBHOOK_URL`) + k6 smoke (`tests/k6/staging.js`)
- Environment promotion ladder defined in `.add/config.json` (production `autoPromote: false`, requires approval)

## Remaining Work

- Production deploy workflow with a health gate that promotes only on a passing post-deploy health check, else rolls back
- One-command rollback (`redeploy-previous-tag` strategy) — documented and tested
- Operational runbook in `ops/` covering deploy, rollback, Redis recovery, and circuit-breaker reset

## Dependencies

- M9 Upstream Resilience (DONE) — circuit breaker + health reporting feed the deploy health gate
- Existing `/health` three-tier status (ok / degraded / error) — the health gate keys off this

## Risks

| Risk | Mitigation |
|------|-----------|
| Health gate passes a degraded deploy | Gate on `status == "ok"`, not just HTTP 200 |
| Rollback redeploys a bad previous tag | Pin to last *verified* tag; smoke-test after rollback |
| Production deploy without human approval | `production.autoPromote: false` — approval required (never autonomous) |
